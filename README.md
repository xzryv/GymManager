# GymManager

**System informatyczny do zarządzania siłownią**

## 1. Opis projektu

GymManager to projekt aplikacji webowej, której celem jest usprawnienie zarządzania siłownią. System ma ułatwiać obsługę klientów, kontrolowanie karnetów, zarządzanie trenerami oraz organizację zajęć grupowych.

Projekt realizowany jest zespołowo. Prace obejmują analizę wymagań, przygotowanie User Stories, harmonogramu, implementację aplikacji, testowanie oraz dokumentację.

## 2. Cele projektu

- Usprawnienie zarządzania bazą klientów.
- Ułatwienie kontroli ważności karnetów.
- Uporządkowanie informacji o trenerach i zajęciach.
- Umożliwienie zapisywania klientów na zajęcia grupowe.
- Przygotowanie prostej i czytelnej aplikacji webowej.
- Dokumentowanie postępu prac i współpracy zespołu za pomocą GitHuba.

## 3. Główne funkcjonalności

- **Panel główny** — podsumowanie liczby klientów, karnetów, zajęć i zapisów.
- **Zarządzanie klientami** — dodawanie, przeglądanie i usuwanie klientów.
- **Zarządzanie karnetami** — przypisywanie karnetów oraz sprawdzanie ich statusu i dat ważności.
- **Zarządzanie trenerami** — przechowywanie danych trenerów i ich specjalizacji.
- **Harmonogram zajęć** — tworzenie zajęć z określeniem terminu, trenera i limitu miejsc.
- **Zapisy na zajęcia** — przypisywanie klientów do zajęć oraz kontrola dostępności miejsc.
- **Lista zapisów** — przegląd klientów zapisanych na poszczególne zajęcia.

## 4. Technologie

- **Python** — logika aplikacji.
- **Flask** — framework do tworzenia aplikacji webowej.
- **SQLite** — relacyjna baza danych.
- **HTML** — struktura stron.
- **CSS** — wygląd i układ interfejsu.
- **Git i GitHub** — kontrola wersji, zarządzanie zadaniami i współpraca zespołowa.

## 5. Podział pracy w zespole

Projekt realizowany jest przez trzy osoby. Każdy członek zespołu odpowiada za określony obszar projektu i dokumentuje swój wkład poprzez zadania, commity oraz Pull Requesty.

### Osoba 1 — klienci i karnety
- Rozwój modułu zarządzania klientami.
- Obsługa danych klientów i walidacja formularzy.
- Zarządzanie karnetami oraz kontrola ich ważności.
- Testowanie funkcjonalności klientów i karnetów.

### Osoba 2 — trenerzy i zajęcia
- Rozwój modułu zarządzania trenerami.
- Tworzenie i obsługa harmonogramu zajęć.
- Implementacja zapisów klientów na zajęcia.
- Kontrola limitu miejsc i poprawności zapisów.

### Osoba 3 — interfejs, integracja i dokumentacja
- Rozwój panelu głównego i interfejsu użytkownika.
- Integracja modułów aplikacji.
- Testowanie współpracy poszczególnych funkcjonalności.
- Przygotowanie dokumentacji i instrukcji uruchomienia.


## 6. Organizacja pracy na GitHubie

GitHub jest wykorzystywany do planowania i dokumentowania realizacji projektu.

- **Issues** — wymagania, User Stories i zadania do wykonania.
- **GitHub Projects / Roadmap** — harmonogram projektu i terminy realizacji.
- **Branches** — oddzielne gałęzie do rozwijania poszczególnych funkcjonalności.
- **Pull Requests** — zgłaszanie i sprawdzanie zmian przed połączeniem ich z główną gałęzią.
- **Commits** — historia zmian w kodzie i dokumentacji.


## 7. Harmonogram projektu

Termin oddania projektu: **22 stycznia 2027 r.**

Główne etapy:
1. Analiza wymagań i przygotowanie User Stories.
2. Projekt architektury oraz bazy danych.
3. Implementacja obsługi klientów i karnetów.
4. Implementacja trenerów, zajęć i zapisów.
5. Rozwój interfejsu oraz integracja modułów.
6. Testowanie, poprawki i dokumentacja końcowa.

Szczegółowy harmonogram jest prowadzony w GitHub Projects w widoku Roadmap.
